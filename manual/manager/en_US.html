Retreat manager manual

You manage one or more retreats: you have full control of each of them. You set up the retreat, add the attendants, decide who on the team has access and look after the letters, from the moment they are requested until the retreat is over and the data is deleted. Letters arrive encrypted and nobody can read them on screen: they can only be seen when printed.

1. How it works

  1. The retreat has its own settings: name, location, dates, the message for letter writers and the other texts on the form.
  2. You add the attendants, one by one or by importing a CSV file.
  3. Each attendant has a private URL for receiving letters. You copy it from the attendants list and pass it on to their family and friends, usually through their emergency contact.
  4. The writer opens the link in any browser, without signing up. They write their letter or attach photos and documents, and send it.
  5. The letter is stored encrypted. The admin area only shows who sent it, when, and what kind of letter it is; never its content.
  6. During the retreat the letters are printed and handed out to each attendant. Every print is logged.
  7. When it's over, you empty the retreat: the attendants and their letters are deleted, and the settings stay ready for the next edition.

Everything lives under the Retreats menu in the WordPress dashboard. All Retreats shows the retreats where you have any permission.

2. What you can do

Permissions are granted per retreat: you can manage one retreat and see nothing of another. In the retreats you manage you can do everything, except what is reserved for plugin administrators: creating and deleting retreats, the global settings and the privacy page.

You can give your team access with any of these three profiles:

  • Message Manager: for whoever looks after the letters. They print them, delete them if needed and return them by email. In the attendant records they can only change the physical letters, the custom fields they are allowed to edit and the contact log.
  • Read Only: for people who need to look things up without changing anything; for example, whoever hands out the links to the families. They see the attendants, the letter counts and the contact log, and can copy each attendant's message URL and invitation message. They can't change anything or open letters.

3. Setting up the retreat

In All Retreats, click Edit or the retreat name. These are the fields:

Retreat Name, Location, Start Date, End Date
The basics. The name and dates are required, and the end date can't be earlier than the start date.
Custom Message for Letter Senders
Text shown to the writer above the form. Use it to explain what the letter is about, when it will be delivered or what tone works best. HTML is allowed.
Legal Disclaimer Text and Disclaimer Acceptance Text
If you write a legal disclaimer, the form shows it with a checkbox that must be ticked before sending. The acceptance text is what appears next to that checkbox (by default, "I accept the terms and conditions").
Multilingual Form
When enabled, the writer sees the form in their browser's language or in the one they pick from a selector (Spanish, Catalan, Basque, Galician, English, Portuguese, French, Italian and German). When disabled, the form is always shown in the site's main language. See Translations of the retreat texts.
Enable Notes Field
Adds a notes field to each attendant, shown in the list and included in CSV import and export.
Enable Internal Notes Field
The same, but these notes are never imported or exported through CSV. Use it for anything that shouldn't leave the admin area.
Message Request Template
Text the team sends to the family or emergency contact asking them to write and to encourage others to do the same. It supports placeholders that are replaced with each attendant's details: [attendant_name], [attendant_surnames], [emergency_contact_name], [messages_url], [retreat_name], [retreat_start_date] and the others listed under the field, including those for custom fields ([slug]). If the template has any text, an Invitation Message button appears in the attendants list.
Letter Return Email Subject and Letter Return Email Text
The email sent to a letter writer when the attendant withdraws and the letter is returned. It supports placeholders such as [sender_name], [attendant_name], [retreat_name] or the date the letter was sent. If you leave it empty, a default text is used. See Returning letters by email.
Custom Header Block, Custom Footer Block and Additional Body Classes
They change the look of this retreat's letter form. They only appear if a plugin administrator has enabled per-retreat customization; otherwise, the form uses the header and footer shared by all retreats.

Save with Update Retreat. From the same screen, Manage Attendants takes you to the attendants list.

Translations of the retreat texts

The custom message, the legal disclaimer and its acceptance text are written in the site's main language. If the form is multilingual, you can write a version for each language under Translations of These Texts. Tabs marked "(written)" already have text.

  • Translate automatically fills in that language's fields from the original so you can review them before saving. It only works if a plugin administrator has set up automatic translation with DeepL.
  • If a language is left empty, the form uses the automatic translation (if configured) or, failing that, the original text.
  • Each automatic translation is done once and saved; it is only redone if you change the original. Only these retreat texts are sent to DeepL, never letters or personal data.

Custom attendant fields

You can add your own fields to the attendant record (for example, T-shirt size, group, allergies or whether they need transport). Click Add Field and fill in:

  • Name and Slug: the slug identifies the field in CSV files and in the request template, as [my_field].
  • Type: text, long text, number, date, yes/no or a list of options (one option per line).
  • Visible to and Editable by: retreat managers only, or message managers too. Read-only users see the fields visible to message managers, but can't edit them.
  • Show in attendants list and Sortable.
  • Import from CSV and Export to CSV.

Remove field deletes its values for every attendant when you save the retreat. You'll be asked to confirm.

4. Access management and invitations

On the retreat edit screen, the Access Management box shows who has permission and lets you grant it.

Current permissions

A list of users with their profile and who granted it. Revoke removes it. You can't revoke your own permissions.

To change someone's access level, pick another one in the drop-down with their profile; the change applies straight away. You can change everyone's except your own and that of the other retreat managers, which only a plugin administrator can change.

Giving access to an existing user

  1. Under Grant Access > Existing Users, search by username, email or name (at least two letters).
  2. Pick the user and the profile: Retreat Manager, Message Manager or Read Only.
  3. Click Grant.

Inviting someone new

  1. Under Invite New Users, enter their email and pick the profile.
  2. Click Send Invitation. They get an email with a link that expires after 7 days.
  3. When they open the link, they fill in their name and click Accept Invitation. If their email already belongs to a user on the site, they simply get the permission; if not, an account is created and they receive their login details by email.

Invitations not yet accepted appear under Pending Invitations, with their expiry date, and can be cancelled. Expired ones are cleaned up automatically.

Give each person the lowest profile that is enough for them. Granting and revoking a permission, and every step of an invitation, are recorded in the audit log.

5. Attendants

The attendants list

Open it with the retreat's Attendants button. At the top you'll see the total number of attendants and a letter summary: how many messages have been received, how many are still to be printed and the total including physical letters.

There are two tabs: Attendants (the active ones) and Withdrawn attendants.

Columns

  • First Name, Last Name, Date of Birth, Emergency Contact, Invited By, Incompatibilities, Notes and Internal Notes (if enabled), plus any custom fields marked for the list.
  • Messages: letters received through the website and, in brackets, those still to be printed. Clicking the header repeatedly sorts by total or by letters pending printing.
  • Physical Letters: paper letters received outside the website.
  • Total Letters: the sum of the two previous columns.
  • Contact Log: a notebook icon with the number of entries. Click it to open the log in a pop-up window.

The headers stay in place as you scroll down the list. On narrow screens the table turns into cards and a Sort by drop-down appears.

Searching, filtering and sorting

The search box looks in first name, last name, emergency contact, invited by and incompatibilities. Under Filters you can filter by each of those fields and by notes and internal notes; click Apply Filters or Clear Filters. Click a column header to sort by it.

Filters also lists the retreat's custom fields that you can see. Text fields are filtered by what they contain; Options list and Yes/No fields, with a drop-down; numbers and dates, with a From–To range in which you can fill in just one end.

Reordering columns

Drag the headers by their handle (it appears when you hover over them). The order is saved for everyone using that retreat. Restore default order puts it back the way it was.

Inline editing

Click a cell to edit it without opening the record: Enter saves, Esc cancels and, in long text fields, Ctrl+Enter saves. You can edit first name, last name, date of birth, invited by, incompatibilities, notes, physical letters and custom fields this way.

Buttons for each attendant

  • Edit: opens the record.
  • Messages: opens their letters.
  • Invitation Message: shows the request template filled in with their details and link, ready to copy and paste into an email or WhatsApp. It only appears if the retreat has a template.
  • Generate Message URL or Copy Message URL: see below.
  • Withdraw: see Withdrawals.

Adding or editing an attendant

Click Add New Attendant or Edit in their row. The fields are:

  • First Name, Last Name and Date of Birth (required).
  • Emergency Contact: first name (required), last name, phone (required), email and relationship to the attendant. This is usually the person who receives the link for the letters.
  • Invited By: who invited them to the retreat.
  • Incompatibilities: attendants they'd better not be placed with, for example at the same table or in the same room.
  • Notes and Internal Notes, if the retreat has them enabled.
  • The retreat's custom fields.
  • Physical Letters Received: the number of paper letters received outside the website.

The record also shows the number of messages received (with a link to them), the Message URL and the Contact Log. If a field fails validation, the form keeps everything you typed and you only need to fix that field.

The message URL

Each attendant has a unique address, something like https://yourparish.org/messages/secret-code, which is the way in to write to them. The code is random and can't be guessed.

  • If the attendant doesn't have one yet, click Generate Message URL.
  • Copy Message URL copies it to the clipboard with the attendant's initials at the end (for example, …/messages/code/#JGP), so you know whose link it is without showing their name.
  • Share the link only with people who should write. Anyone who has it can send letters to that attendant.
  • The URL keeps working until the attendant is withdrawn or deleted.

Contact log

This is where the team writes down calls and conversations with each attendant's contact person: "Called his mother on Tuesday, she'll send the link to his brothers", and so on. Open it from the Contact Log column in the list or from the record.

  • Add entries with a date and a description using Add Entry.
  • You can edit or delete any entry, including other people's, and see the full Change history, including deleted entries. Edited entries are marked "(edited)".
  • Message managers can write entries and correct their own for 15 minutes. Read-only users can read it, but not write in it.

6. Importing and exporting attendants (CSV)

Importing

In the attendants list, click Import CSV. The file:

  • Must have the column names in the first row. They can be in any order, in English or in the admin language, and unrecognised columns are ignored.
  • Needs these columns: First Name, Last Name, Date of Birth, Emergency Contact Name and Emergency Contact Phone.
  • Can also include: the emergency contact's last name, email and relationship, invited by, incompatibilities, notes and any custom fields marked for import (by their slug).
  • Can be up to 2 MB.

Dates. Accepted formats are YYYY-MM-DD, DD/MM/YYYY, MM/DD/YYYY, DD-MM-YYYY, MM-DD-YYYY and DD.MM.YYYY. A date like 01/10/2025 could be 1 October or 10 January; choose how to read it under Date Format Preference, or better still, use YYYY-MM-DD. When the import finishes, the result warns you about any ambiguous dates it found.

Attendants who already exist. If a row matches an attendant in the retreat (same first name, last name and date of birth), it isn't duplicated: their emergency contact details and custom fields are updated. Rows matching withdrawn attendants are left as they were.

When it finishes, it shows how many attendants were added, how many were updated and which rows had errors, with their line numbers.

Exporting

Export CSV downloads the active attendants with their details, their message URL, the number of messages and any custom fields marked for export. Internal notes are never exported. Bear in mind that the file contains personal data and the private URLs: keep it safe and delete it when you no longer need it.

7. The letter form

This is the page people see when they open an attendant's message URL. No account on the website is needed. It's worth knowing it well so you can help the families.

  • At the top are the attendant's name and the retreat's custom message.
  • If the form is multilingual, there is a Language selector. Changing the language doesn't reload the page, so nothing already written is lost.
  • The writer enters their name and, optionally, their email (twice, to avoid typos). The email is stored encrypted and is only used to let them know about any problem with their letter, such as it being returned if the attendant doesn't end up going on the retreat.
  • They choose the message type:
    • Text Message: an editor with bold, italic, underline, lists and undo/redo. Images and text copied from Word or Google Docs can be pasted in.
    • File Upload: photos or documents (PDF, DOC, DOCX, TXT, JPG, PNG, GIF). The form shows the maximum size the server accepts.
  • They solve the Security Check, a simple sum. Users logged in to the website don't see it.
  • If the retreat has a legal disclaimer, the acceptance box must be ticked; the send button stays disabled until then.
  • After clicking Send Confidential Message, a page confirms that the letter has been received.

To prevent abuse, each IP address can send a limited number of letters per hour. If someone gets blocked, they can wait an hour or ask a plugin administrator to lift the block.

If the attendant has withdrawn, the form shows "Messages are no longer being accepted for this attendant." An address with a code that doesn't exist returns a 404 error.

8. Confidential messages: printing, deleting and returning

The messages list

Open it with each attendant's Messages button. For security, it never shows the content of the letters, only their details: sender, type (text or files), date sent and print status. You can filter by type, search by sender and sort by any of those columns, including print status (unprinted first).

Printing

  1. Click Print on the letter.
  2. A new tab opens with the letter ready to print: recipient, sender and content. It is decrypted at that moment.
  3. The browser's print dialog opens. When you close it, the tab closes by itself.
  • Letters with several images are laid out so that no image is split across two pages.
  • If the letter is a single PDF, a "From/To" header is usually added at the top so you know who it's from and who it's for.
  • If there are several files and any of them isn't an image, they are all downloaded together in a ZIP file. Word documents can't be shown in the print view: download them and print them separately.
  • Use an up-to-date browser (Edge, Chrome, Firefox or Safari). Internet Explorer is not supported and won't show the letters.

Print history

Each letter's status tells you whether it has been printed, how many times and when it was first printed. Click it to see the full history: who printed it, when and from which IP. Print each letter only once if possible and keep the paper copies safe.

Deleting a letter

Delete removes the letter, its files and its print history. It can't be undone.

Returning letters by email

When an attendant withdraws (for example, because they end up not going on the retreat), their letters can be returned to the people who wrote them, as long as they left their email:

  • Return by email returns one letter; Return all by email returns every letter that can be returned.
  • Before sending, a preview shows the recipient, subject, text and attachments. Text letters are attached as an HTML document; file letters, with the original files.
  • Once the email is sent, the letter is deleted from the system. If sending fails, the letter is kept.
  • If the letter had already been printed, you're reminded to destroy the paper copy.
  • Letters without an email are shown as "No email: cannot be returned".

The email subject and text are set up in the retreat (see Setting up the retreat).

9. Withdrawals, reactivations and the end of the retreat

Withdrawing an attendant

If someone isn't going on the retreat, click Withdraw in their row. The attendant:

  • moves to the Withdrawn attendants tab, with the date and the user who withdrew them;
  • can no longer be edited;
  • stops accepting letters through their URL;
  • keeps their letters, which can still be printed or returned by email, and their contact log, which stays open.

Nothing is deleted. From that tab you can Reactivate the attendant or Delete Permanently. Only withdrawn attendants can be deleted; if they still have letters that could be returned, you're warned before they are deleted.

Withdrawing all attendants

Withdraw All Attendants does the same for the whole retreat. To confirm, you have to type "WITHDRAW ALL ATTENDANTS".

Emptying the retreat

Once the retreat's end date has passed, the Empty Retreat button appears. It permanently deletes all attendants, active and withdrawn, along with their letters, files, print history, contact log and custom field values. The retreat keeps its settings, custom fields and managers, ready for next time.

To confirm, you have to type the exact name of the retreat. If there are still letters from withdrawn attendants that could be returned, you're warned first.

If the whole retreat needs to be deleted, settings included, ask a plugin administrator.

10. A retreat from start to finish

  1. Weeks before. Empty last year's retreat if it still has data, and review the message for letter senders, the legal disclaimer and the request template. Give the team access with the profile each person needs.
  2. Registration. Add the attendants or import them from a CSV file.
  3. Asking for letters. For each attendant, copy the Invitation Message and send it to their emergency contact. Note in the contact log who you've called or written to.
  4. Follow-up. Check the list for anyone with few letters (sort by Total Letters) and get back in touch if needed. Record paper letters under Physical Letters.
  5. Withdrawals. If someone isn't going, withdraw them and return their letters by email.
  6. During the retreat. Print the letters (sort by Messages to see those still to be printed) and get them ready to hand out.
  7. Afterwards. Destroy any spare copies and click Empty Retreat to delete the personal data and leave the retreat ready for next time.

11. FAQ and troubleshooting

Who can read the letters?

Nobody, on screen. They can only be seen when printed, and only that retreat's retreat managers and message managers and the plugin administrators can print them. Every print is logged.

A relative says the link doesn't work.

Check that they copied the whole address and that the attendant hasn't been withdrawn. If they see "Too many requests", they should wait an hour, or you can ask a plugin administrator to reset the limits.

Uploading files gives a size error.

The limit is set by the server and shown on the form. Send smaller files, or fewer at a time.

I can't see the Invitation Message button.

It only appears if the retreat has a Message Request Template.

I can't edit an attendant.

They've been withdrawn. Reactivate them from the Withdrawn attendants tab.

I can't see the Empty Retreat button.

It only appears once the retreat's end date has passed.

I can't see a retreat in the list.

You only see the retreats where you have permission. Ask its manager or a plugin administrator for access.

Is the form in my language?

The form is translated into Spanish, Catalan, Basque, Galician, English, Portuguese, French, Italian and German. The retreat's own texts have to be written or translated (see Translations).
